# Интерфейс Smart Mixer на ноутбуке

Цель до презентации — полноценное управление миксером с ноутбука по USB.
Интерфейс написан на C++ и LVGL **9.2.2**, размер окна **800×480** совпадает
с CrowPanel. Общие экраны находятся в `shared/SmartMixerUi/`; Linux/SDL и USB
вынесены в этот каталог. Прошивка `display_controller/` сохранена.

## Запуск

Нужны CMake, C/C++ compiler, pkg-config, SDL2 с заголовками и исходники LVGL
9.2.2. На текущем ноутбуке эти зависимости доступны. CMake берёт LVGL из уже
установленных зависимостей дисплея, без копирования vendor-demo:
`display_controller/.pio/libdeps/crowpanel_rev3/lvgl`.
Если этого каталога нет, выполнить `pio pkg install -d display_controller`.
Другой путь можно передать в CMake через `-DLVGL_DIR=/путь/к/lvgl`.

Из корня:

```sh
sh desktop_controller/run.sh
# Другой порт, без автоматического подключения:
sh desktop_controller/run.sh --device /dev/ttyACM1
```

Откроется главный экран: «Приготовить напиток», «Добавить рецепт»,
«Прокачка и промывка», «Сервисный режим». В сервисном режиме на вкладке «USB / Журнал» выбрать порт и нажать
«Подключить». Порт вводится с клавиатуры; числа меняются кнопками `−/+` или
клавиатурой. USB работает на 115200, LF. Закрыть Serial Monitor перед подключением.

Колесо мыши или тачпад прокручивают блок под курсором (журнал, состояние, списки).
На вкладке «USB / Журнал» состояние и журнал — отдельные прокручиваемые блоки;
журнал следует за новыми строками, пока его не прокрутили вверх.

На внутренних экранах кнопка со стрелкой возвращает на главную. Общей шапки
нет; сведения о подключении и состоянии находятся в «USB / Журнал».
«Состояние» доступно только в сервисном режиме и переводит на эту вкладку.
«Стоп» появляется при приготовлении или после подтверждённого запуска калибровки
и остаётся доступным при переходах между экранами, пока операция не завершена.
Ошибки заполнения полей показываются отдельным сообщением.

Объём: целое число 1–1000 мл; движение: 1–9999 микрошагов за команду; масса: 0,01–999,99 г
с двумя знаками после точки или запятой. В числовых полях запрещены буквы,
знаки и повторный десятичный разделитель. Пустое значение и выход за диапазон
выделяются красной рамкой и блокируют отправку команды. Стрелки, Home/End,
Backspace и Delete редактируют текст; кнопки `−/+` меняют введённое число.

## Прошивка Arduino для демонстрации

```sh
pio run -d motion_controller -e desktop_usb -t upload
```

`desktop_usb` использует существующее управление механизмами через USB,
но **не выполняет homing автоматически при старте**. Насосы изначально
выключены; мотор включён на удержание. После подключения прочитать состояние,
затем во вкладке «Привод» нажать «Найти верхний ноль» и подтвердить действие.
Работа насосов разрешается Arduino после успешного homing.

Текущая `uart_diagnostics` не управляет механизмами. Приложение распознаёт её
отчёт и блокирует исполнительные кнопки. Обычная `uno_r4_minima` тоже совместима
с приложением, но при старте автоматически выполняет homing.

## Что реализовано сейчас

- Главное меню, каталог, добавление, изменение и удаление рецептов.
- Два режима рецепта: «Слоями» (шток следует уровню) и «Смешать у края»
  (обычный многокомпонентный напиток, шток не опускается). Нужна `MIX_API 3`.
- Экран «Прокачка и промывка»: калибровка времени заполнения трассы каждого
  насоса, прокачка ровно на это время, промывка раствором и затем водой
  на заданное число прогонов трассы, остановка насоса. Время трассы и названия
  ингредиентов насосов сохраняются на ПК.
- Сохранение рецептов между запусками; кириллические названия.
- Приготовление двух слоёв с отслеживанием высоты, подтверждённым завершением
  и отменой. Для этого нужна обновлённая `desktop_usb`, объявляющая `MIX_API 3`
  (с `MIX_API 2` работают только слоёные рецепты).
- Дозирование заданного объёма каждым насосом; постоянное включение/выключение.
- Движение вверх/вниз, поиск верхнего нуля и режим энкодера.
- Прокачка, замер 20 секунд, сохранение массы с точностью 0,01 г, проверка 50 мл.
- Сбор, просмотр и очистка таблиц высоты.
- Состояние и журнал ответов Arduino с кириллицей.
- Подтверждение поиска нуля и изменений EEPROM; блокировка исполнительных
  кнопок до обнаружения рабочей прошивки; отсутствие автоматических повторов команд.

Состояние читается кнопкой, а не непрерывно. Команда «отправлена» означает
передачу байтов, результат нужно смотреть в ответе Arduino. Флаг насоса в
текущем `status` отражает постоянное включение, а не ход дозирования по таймеру.

Кнопка «СТОП / ОТМЕНА» отправляет `s`. В приготовлении она отменяет налив
и движение; шток остаётся на месте с удержанием. Во время сервисных `homeUp()` и
`moveActuator()` Arduino не принимает эту команду; для немедленной остановки
двигателя нужно отключение силового питания. При штатном отключении порта
и выходе приложение пытается отправить `s`. В рецепте дополнительно работает
watchdog 2 секунды; ручное сервисное управление такого watchdog пока не имеет.
Перед выходом остановить насосы.

## Рецепты и хранение

Рецепт содержит название (до 32 символов / 64 байт UTF-8), объёмы насосов 1 и 2,
выбор, какой насос наливает первым, и режим: «Слоями» или «Смешать у края».
В режиме «Смешать» оба компонента наливаются по очереди со штоком у края рюмки,
без опускания; таблица высоты всё равно нужна — она задаёт край и объём рюмки. Объёмы всегда относятся к физическим насосам
1 и 2; смена порядка не меняет их местами. Уровень определяется одной общей
калибровкой «объём → положение штока» в Arduino.
Ноль означает пропуск насоса; оба объёма нулевыми быть не могут. Сохраняется до
32 рецептов. Одинаковые названия запрещены. Перед запуском показывается состав,
суммарный объём и напоминание установить подходящую ёмкость.

На Linux файл: `$XDG_DATA_HOME/smart-mixer/recipes.txt`, по умолчанию
`~/.local/share/smart-mixer/recipes.txt`. Путь можно изменить:

```sh
sh desktop_controller/run.sh --recipes /путь/к/recipes.txt
```

Формат — версионный UTF-8 текст: заголовок `SMART_MIXER_RECIPES 3`, затем строки
`id объём1 объём2 первыйНасос слои(1)/смешать(0) название`. Файлы v2 читаются как
слоёные рецепты. Старый формат v1 читается с прежним порядком 1→2; его поле таблицы
игнорируется, а не превращается в порядок насосов.
Чтение не изменяет файл; явное сохранение переводит каталог в v3.

Названия ингредиентов и время трассы насосов хранятся рядом, в `channels.txt`
того же каталога: заголовок `SMART_MIXER_CHANNELS 2`, строки `1 секунды название`
и `2 секунды название`. `0.00` — трасса не откалибрована, пустое название — не задано.
Файл v1 (`1 название`, без времени) читается; первое сохранение переводит его в v2.
Эти данные в EEPROM Arduino не записываются: приложение передаёт только длительность
каждого запуска.
Сначала записывается временный файл рядом,
выполняется fsync, затем атомарная замена. Каталог в памяти обновляется только
после успешной записи. Повреждённый файл не перезаписывается автоматически:
операции сохранения блокируются до исправления и перезапуска. Резервную копию
можно сделать обычным копированием файла при закрытом приложении.

Модель `Recipe` и экраны не зависят от файловой системы ПК. Для CrowPanel позже
нужен адаптер её постоянного хранилища; рецепты не записываются в EEPROM Arduino.

## Прокачка и промывка

Экран доступен с главного меню. Кнопки насосов активны после подключения
рабочей прошивки; Arduino выполняет их только после поиска верхнего нуля.

- **Калибровать** — один раз для каждого насоса, на пустой трассе с трубкой в
  жидкости. Отправляется `cal prime N`; отсчёт идёт от ответа Arduino
  `Запущено: PN PRIME`. **Жидкость пошла** отправляет `s` и сохраняет прошедшее
  время (0,5–300 с). Остановка другим способом замер не сохраняет.
- **Прокачать** — после замены ёмкости: насос работает ровно время трассы
  (`tN секунды`).
- **Промывка** — «Раствором», затем «Водой»: насос работает время трассы ×
  число прогонов (1–10, по умолчанию 2, не больше 600 с), после подтверждения.
  «Остановить насос» отправляет `s`.
- Внизу экрана показаны состояние подключения и последний ответ Arduino.

Команду `tN` отсчитывает сама Arduino, поэтому обрыв USB не оставляет насос
включённым. Она есть в прошивке с `MIX_API 3`; со старой прошивкой приложение
не отправляет её. Время трассы зависит от длины трубки и жидкости: после замены
трубок калибровку нужно повторить.

## Движение при приготовлении

Одна общая таблица высоты применяется к **суммарному** объёму смешанных жидкостей.
Она должна относиться к используемой ёмкости. Верхний край
рюмки — самая верхняя точка этой таблицы, а не ноль верхнего концевика.

1. Arduino проверяет homing, калибровку насосов, таблицу высоты и отсутствие
   другой операции; только после этого начинает движение.
2. Шток выходит к краю рюмки; выбранный первым насос наливает слой без движения штока.
3. После остановки первого насоса шток опускается к уровню первого слоя.
4. Другой насос наливает второй слой; шток поднимается по общей таблице высоты.
5. Насосы выключаются, шток возвращается к краю; после этого приходит DONE.

Поправка «на 5 мл выше уровня» пока не применяется. Для двух слоёв объём первого
должен быть не меньше первой точки таблицы, а общий объём — не больше последней.
Кривая должна содержать минимум две точки, с возрастающим объёмом и неубывающим
положением не выше 0 (верхний концевик). Программного нижнего предела хода нет:
ход вниз ограничен только механикой. Экстраполяции вне таблицы нет.
При одном компоненте он наливается у края, без опускания. Объёмы рассчитаны
по времени и коэффициенту насоса; датчика фактического расхода нет.

Исполнитель `shared/SmartMixerControl/src/RecipeExecution.h` делает максимум
один микрошаг за проход, оставляя обработку USB/STOP между импульсами. Движение
ограничено 30 секундами на этап, налив — 30 минутами на насос. Отмена или ошибка
останавливают насосы и движение без автоматического возврата; удержание сохраняется.

Временный USB API v3: `mix id млНасоса1 млНасоса2 первыйНасос слои`, где `слои` — 1
(слоями) или 0 (смешать у края). Форма API v2 без последнего числа по-прежнему
принимается и означает «слоями». Heartbeat `lease id` каждые 250 мс,
ответ `MIX id PHASE процент причина`. Фазы: POSITIONING, FIRST, LOWERING, SECOND,
RETURNING, DONE, CANCELLED, ERROR. В рецепте Arduino останавливается через 2 с
без heartbeat; ПК через 1,5 с без отчёта отправляет STOP. Повтор текущего ID
возвращает состояние, повтор последнего завершённого ID отклоняется. Это не
постоянная история операций и не защита exactly-once через перезагрузку.
Команды автоматически не повторяются; после разрыва связи нет возобновления.
Во время рецепта сервисные исполнительные команды и энкодер не управляют механизмами.
Фазы FIRST/SECOND обозначают порядок слоёв, не номера физических насосов.
В режиме «Смешать» фазы LOWERING нет.
ПК не запускает рецепт на старой прошивке `MIX_API 1`, где последний аргумент
означал таблицу высоты. После обновления программы нужно загрузить новую `desktop_usb`.

Этот API применяется только в `desktop_usb`; он не заменяет спецификацию
общего кадрированного протокола v1 и не добавлен в UART-диагностику CrowPanel.

## До полноценной презентации

Код приготовления и хранилища проверен без оборудования. Реальные движение,
объём порций, watchdog и новый интерфейс с Arduino ещё требуют стендовой проверки.
Следующие этапы:

1. Проверить USB-управление на реальной Arduino без нагрузки, затем на механизмах.
2. Подтвердить цикл слоёв, отмену на каждом этапе, обрыв USB и возврат к краю
   на механизмах; перевести сервисные HOME/MOVE на общий асинхронный исполнитель.
3. Подключить общий протокол через USB отдельным адаптером. Временно используется
   прежний текстовый Serial API; его замена не должна менять экраны.
4. Добавить удобный перенос рецептов (названия ингредиентов уже привязаны к насосам).
5. Довести компоновку и сценарий демонстрации, проверить дозирование и повторные запуски.
6. После приезда CrowPanel подключить `SmartMixerUi` к её LVGL и UART-адаптеру,
   сохранив рабочий RGB/GT911 драйвер. Проверить сенсор, память и отрисовку на панели.

Шаг переноса не требует переписывать виджеты из другого UI framework.
Настройки USB и журнал ПК при переносе нужно адаптировать для UART панели.
До проверки исполнительного протокола существующий диагностический экран
CrowPanel остаётся рабочей точкой возврата.

## Проверки без оборудования

```sh
cmake -S desktop_controller -B /tmp/smart-mixer-desktop-build
cmake --build /tmp/smart-mixer-desktop-build --parallel 4
ctest --test-dir /tmp/smart-mixer-desktop-build --output-on-failure
```

`usb_pty` проверяет реальный POSIX serial I/O через виртуальную пару портов:
распознавание прошивки, блокировку диагностики, частичные UTF-8 строки,
формат дозирования, отключение и отсутствие повтора дозы после подключения.
`recipes` проверяет сохранение/чтение/изменение/удаление, ошибки файла и исполнение
слоёв в обоих порядках с общей калибровкой, разными длительностями насосов,
возвратом, отменой и watchdog на каждом этапе; также переход рецептов v1→v2.
`calibration_eeprom` проверяет настоящую логику EEPROM на имитации памяти:
отдельные коэффициенты, единую таблицу и миграцию без записи при старте.
`usb_pty` также проверяет capability, ID ответов, heartbeat, отмену и DONE.
`ui_smoke` отрисовывает главное меню, каталог, редактор, экран прокачки и промывки
и четыре сервисных вкладки
SDL dummy-драйвером, без доступа к плате.
`input_keyboard` проверяет через SDL-драйвер фокус мышью, клавиатуру всех пяти
полей, отсутствие задвоения, фильтрацию, десятичный ввод, диапазоны и передачу
в команду именно набранного числа.
Дополнительно проверяются русское название рецепта, сохранение редактора,
режим рецепта, пустой состав, подтверждение приготовления, прокачка и промывка
выбранного канала и сохранение названия ингредиента. ПК-драйвер `SdlKeyboard.cpp`
передаёт целые UTF-8 символы; vendor-файлы LVGL не изменяются.
Снимки вкладок сохраняются в `/tmp/smart-mixer-ui-tab-0.bmp` … `-3.bmp`.
Главное меню/каталог/редактор/прокачка: `/tmp/smart-mixer-ui-page-0.bmp` … `-3.bmp`.
Эти проверки не подтверждают движение или налив на реальном оборудовании.
