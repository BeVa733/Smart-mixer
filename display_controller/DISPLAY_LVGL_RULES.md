# Правила разработки для CrowPanel 7″ Rev3 и LVGL

Документ относится к Elecrow CrowPanel ESP32 7″ Basic Rev3:
ESP32-S3-WROOM-1-N4R8, RGB 800×480, GT911 и 8 МБ OPI PSRAM.

## Базовая архитектура

1. RGB-панель работает как непрерывный видеовыход. Контроллер LCD постоянно
   читает framebuffer через EDMA; это не SPI-дисплей, которому можно без
   синхронизации отправлять отдельные прямоугольники.
2. Для LVGL используются два полноэкранных RGB565 framebuffer:
   `800 × 480 × 2 = 768000` байт каждый. Оба выделяет `esp_lcd` в PSRAM.
3. LVGL получает эти framebuffer напрямую и работает в
   `LV_DISPLAY_RENDER_MODE_FULL`. Дополнительный промежуточный framebuffer и
   копирование кадра не нужны.
4. Пока LCD выводит один framebuffer, LVGL рисует во втором. Готовый буфер
   передаётся `esp_lcd_panel_draw_bitmap()`, а завершение flush подтверждается
   только после события VSYNC.
5. Внутренний bounce buffer на 10 строк сглаживает краткие задержки доступа к
   PSRAM. Он дополняет двойную буферизацию, а не заменяет её.

## Что запрещено в основном интерфейсе

- Нельзя рисовать LVGL прямо в framebuffer, который в этот момент выводит LCD.
- Нельзя использовать один PSRAM-framebuffer и копировать в него области из
  callback `flush`: это вызывает tearing, сдвиг строк и рябь при нагрузке.
- Нельзя вызывать `lv_display_flush_ready()` до постановки готового кадра на
  вывод и синхронизации с VSYNC.
- Нельзя выделять собственные полноэкранные буферы поверх двух буферов
  `esp_lcd`: это расходует PSRAM и создаёт лишний трафик памяти.
- Нельзя менять RGB-тайминги, порядок data pins или полярности отдельно от
  конфигурации конкретной ревизии платы.

## Память и производительность

- OPI PSRAM обязательна. При запуске проверяются `psramFound()` и объём 8 МБ.
- Формат LVGL и панели должен совпадать: RGB565, 16 бит на пиксель.
- Размер framebuffer рассчитывается из формата пикселя: для RGB565 это строго
  `width × height × 2`. В LVGL 9.2 нельзя использовать `sizeof(lv_color_t)`:
  внутренний тип цвета не обязан иметь размер пикселя выбранного display format.
- PCLK в текущей Arduino-конфигурации Rev3 равен 24 МГц. При добавлении тяжёлых
  операций с flash/PSRAM нужно измерять устойчивость RGB-потока; снижение PCLK
  допустимо только как осознанная настройка частоты обновления, а не как лечение
  неправильной буферизации.
- Обновления виджетов выполняются через API LVGL. Прямой доступ к активному
  framebuffer вне display-драйвера запрещён.
- Долгие вычисления, файловые операции и сетевые обработчики не должны
  блокировать вызовы `lv_timer_handler()`.

## Порядок запуска Rev3

1. Подсветка `GPIO2` удерживается выключенной.
2. I²C запускается на `SDA GPIO19`, `SCL GPIO20`.
3. PCA9557 по адресу `0x18` выполняет последовательность Rev3:
   оба сигнала становятся выходами и опускаются; через 20 мс `IO0` поднимается;
   через 100 мс `IO1` переводится во вход.
4. Инициализируется RGB-панель, два framebuffer и VSYNC callback.
5. Проверяется GT911 по адресу `0x5D`, резервный адрес — `0x14`.
6. Инициализируется LVGL, framebuffer передаются ему в режиме `FULL`.
7. Создаётся интерфейс, выполняется первый кадр, затем включается подсветка.

## Правила для сенсора

- GT911 опрашивается через I²C; готовность данных находится в `0x814E`, первая
  точка начинается с `0x814F`.
- После обработки пакет подтверждается записью нуля в `0x814E`.
- В каждом чтении LVGL явно передаётся `PRESSED` или `RELEASED`; нельзя оставлять
  неопределённое предыдущее состояние.
- Преобразование координат хранится в одном месте. Для текущей ориентации Rev3
  используются нативные X/Y без swap и mirror.

## Проверка изменений

Перед загрузкой прошивка должна успешно собираться командой `platformio run`.
В UART-диагностике GPIO43/44 заняты протоколом: текстовый Serial-лог запуска
отключён. После загрузки проверять экран, отклик GT911 и счётчик VSYNC=0;
проверку внутренних адресов framebuffer/PSRAM делать через отладку или отдельную
тестовую сборку, не смешивая printf с рабочими пакетами.

Любое изменение интерфейса проверяется серией быстрых нажатий и обновлений
виджетов. Экран не должен рябить, сдвигаться или показывать части двух кадров.
